# Student Guide

## How to study this course

For each module:

1. Read all four tutorials.
2. Type the examples rather than copy-pasting blindly.
3. Complete the lab without looking at the solution first.
4. Run the tests.
5. Take the quiz before opening the answer key.
6. Write one short reflection: what failed, why, and what you changed.
7. Commit your work to your own GitHub portfolio.

## Definition of done

A project is not done because the happy path works. A strong submission includes:

- a README with problem, users and architecture;
- reproducible setup;
- input validation;
- tests;
- safe handling of secrets;
- failure behavior;
- at least one evaluation dataset;
- sample output or screenshots;
- a short demo script;
- a section called `What I would improve next`.

## Getting help

Before asking for help, capture the exact error, Python version, command you ran, expected behavior and actual behavior. This is a professional engineering habit, not just a classroom rule.
